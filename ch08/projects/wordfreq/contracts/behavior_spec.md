# wordfreq 동작 계약 (behavior spec)

기준 구현: `python_src/wordfreq.py` (3판, 승인일 2026-10-30)
다른 언어로 재구현할 때 아래 항목은 바이트 단위로 같아야 한다. "비교 안 함"으로 적힌 항목만 예외다.

## 1. 명령행

```
wordfreq FILE [--top N] [--json]
```

| 인자 | 의미 | 기본값 |
|---|---|---|
| `FILE` | 읽을 텍스트 파일 경로 (필수) | |
| `--top N` | 출력할 상위 단어 수. 1 이상의 정수(아래 규칙) | 10 |
| `--json` | 텍스트 대신 JSON 한 줄 출력 | 꺼짐 |

`N`은 ASCII 숫자(`0`-`9`)로만 이뤄진 문자열이다. 부호(`+`), 공백, 밑줄(`1_0`), 전각 숫자(`２`) 등 그 밖의 글자가 있으면 인자 오류다. 앞의 0은 무시한다(`007`은 7). 값이 단어 수보다 커도 오류가 아니며, 아주 큰 값(19자리 이상)도 그대로 받는다.

옵션 이름을 줄여 쓰면(`--to`, `--js`) 인자 오류다. 같은 옵션을 여러 번 주면 마지막 값을 쓴다. `--` 뒤의 인자는 모두 위치 인자다.

`-h`·`--help`는 도움말을 stdout에 쓰고 종료 코드 0이다. **도움말 문구는 비교하지 않는다**(터미널 폭에 따라 줄바꿈이 달라짐).

FILE은 Python `pathlib.Path`로 정규화한 경로를 연다. 끝의 `/`와 `/.`는 떼고(`basic.txt/`는 `basic.txt`를 읽음), 중간의 `.` 구간은 지우고, 빈 문자열은 `.`(현재 디렉터리)이 되어 "cannot read file"이다. 오류 메시지의 `<FILE>`은 정규화 전의 원래 문자열이다.

## 2. 단어 규칙

1. 파일 전체를 UTF-8로 읽는다.
2. 공백으로 자른다. 공백의 정의는 Python `str.split()`(인자 없음)과 같다.
3. 각 조각의 **앞뒤**에서 문장 부호를 떼어 낸다. 문장 부호 집합은 ASCII 문장 부호 32자와 `“ ” ‘ ’ … ·` 6자이다. 가운데 있는 것은 남긴다(`don't`, `e-mail`).
4. Python `str.lower()`와 같은 규칙으로 소문자로 바꾼다.
5. 빈 문자열이 된 조각은 버린다.

## 3. 정상 출력 (종료 코드 0)

- 인코딩은 UTF-8, 줄바꿈은 LF(`\n`). 운영체제와 무관하다.
- 정렬: 빈도 내림차순, 빈도가 같으면 단어의 코드 포인트 오름차순.

텍스트 형식 (탭 구분, 마지막 줄 뒤에도 `\n`):

```
words: <전체 단어 수>
unique: <서로 다른 단어 수>
<빈도>\t<단어>
...
```

JSON 형식 (`--json`, 공백 없는 한 줄 + `\n`, 한글은 이스케이프하지 않음):

```
{"words":5,"unique":3,"top":[{"word":"rust","count":2}]}
```

## 4. 오류 (stderr, stdout은 비어 있어야 함)

| 상황 | stderr (정확히 일치) | 종료 코드 |
|---|---|---|
| 파일 없음 | `wordfreq: error: file not found: <FILE>` | 1 |
| UTF-8이 아님 | `wordfreq: error: not valid UTF-8: <FILE>` | 1 |
| 그 밖의 읽기 실패(디렉터리 등) | `wordfreq: error: cannot read file: <FILE>` | 1 |
| 인자 오류(FILE 누락, `--top 0`, `--top abc`, `--top ２` 등 1절 규칙 위반, 모르는 옵션) | 비교 안 함(비어 있지만 않으면 됨) | 2 |

`<FILE>`은 사용자가 입력한 경로 문자열이다. 경로가 UTF-8이 아닌 바이트를 포함하면 잘못된 부분을 U+FFFD(`�`)로 바꿔 출력한다. 바꾸는 단위는 Unicode 표준이 권장하는 방식(잘못된 바이트 열의 최대 부분 하나당 U+FFFD 하나)이며, Python의 `bytes.decode("utf-8", "replace")`와 Rust의 `String::from_utf8_lossy`가 이 방식을 따른다.

## 5. 출력 실패

stdout에 쓰다가 실패하면(읽는 쪽이 파이프를 먼저 닫음, 디스크가 가득 참 등) 종료 코드는 0이 아니어야 한다. stdout에 이미 나간 내용과 stderr 내용은 비교하지 않는다. 기준 구현은 `wordfreq: error: cannot write output`을 쓰고 1로 끝난다. 실행이 멈추는 것(panic, 시그널로 인한 종료)은 허용하지 않는다.

## 6. 범위 밖

표준 입력·출력·오류가 닫힌 상태로 실행하는 경우는 비교하지 않는다.
